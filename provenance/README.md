# Export provenance

This repository is a source-only extraction from a larger prayer-time research workspace. Historical publisher calendars, HTTP responses, and internal working records are not redistributed here.

- [`source-map.json`](source-map.json) records the original research-relative identifier, source SHA-256, destination SHA-256, import rewrites, and declared extraction changes for each transferred file. Research identifiers are provenance labels, not paths promised to exist in this repository.
- [`entrypoints.json`](entrypoints.json) lists the selected native calculation functions and contracts.
- [`relocation-verification.json`](relocation-verification.json) records the local comparison of the original and exported modules, including one complete-output sample for each of the 23 selected entry points. Annual samples compare every day. This verifies extraction equivalence on those inputs; it is not a new comparison with institutional calendars.
- [`wrapper-parity.json`](wrapper-parity.json) extends that check to 163 public-wrapper/original-module comparisons: seasonal and leap-day inputs, northern calendars, several continents, the international date line, polar missing events, both Asr choices for FCNA, the fixed Roseville experiment, and all four Shia angle profiles with both solar engines. Its coordinates are test inputs, not certified institutional calculation points. The stored rendered-output hashes can be checked without the original archive.

The original archive is needed to independently repeat the historical source-to-export comparison. Public contributors can verify the exported hashes with `npm run check` and exercise the included examples, regression cases, and comparison tests with `npm test`. These checks do not independently reproduce the original institution-calendar accuracy measurements.

The public wrappers, CLI, comparison utility, tests, and documentation were added for this repository. They are outside the original-source map and have their own Git history. When intentionally improving a mapped numerical module, record the new version, rationale, validation and source-map lineage together; do not silently change the historical accuracy claim.

The September 2026 [rule-evidence audit](../docs/METHOD-EVIDENCE.md) adds separately named Moonsighting Committee and Banuri Dhuhr adapters around unchanged mapped numerical modules. Their source-supported margins are distinguished from unconfirmed rounding and model-Zawal assumptions. Dedicated tests cover default preservation, event/date semantics and the new options. Historical extraction parity and calendar validation are not claimed as validation of these later variants.

The additive [Diyanet point-consistency diagnostic](../methods/diyanet/diagnostics/README.md) was written for this repository from the separately reviewed inverse-constraint study. It reuses the mapped own USNO routine, has its own tests, and changes no mapped calculation module or institutional preset. The [refinement evidence summary](../methods/diyanet/research/offline-refinement-2026-09-25.json) publishes aggregate comparisons and private artifact hashes, without redistributing reference observations. Its historical point-fit results and rejected alternatives do not replace the validation statistics of the unchanged calculation entries.

The additive [UAE own-ray experiment](../methods/uae-awqaf/OWN-RAY.md) is original JavaScript ray-integration code, with a separate Python radial formulation and generated mathematical fixtures. It reuses the mapped V2 recipe and USNO routine without changing any mapped asset. The original 23-entry extraction and 163-wrapper checks remain historical records, not claimed coverage of this later addition. New regression, offline-runtime and numerical tests cover it separately. Calendar replay aggregates retain all gains and regressions; the older native/PAL study is a numerical benchmark only and is not shipped or called.

The additive [ARC compatibility export](../methods/shia-angles/ARC-COMPATIBILITY.md) relocates the previously frozen original `research/shia-v2/calculate.mjs` numerical body, adding strict public input checks and explicit quality metadata. Its import now uses the already mapped USNO routine. A normalized-body comparison and 2,922-day replay retain all six events’ raw and rounded values, dates and statuses. It is outside the historical 23-entry extraction map and 163-case wrapper record; separate tests and evidence cover the addition. Three new annual forecasts were frozen before source requests; no calendars or client keys enter the public runtime.

The additive [Bayynat nearest wrapper](../methods/bayynat/NEAREST-MINUTE.md) selects an already present recipe from the unchanged mapped candidate engine, adding explicit research metadata. It is outside the historical 23-entry extraction record. Separate tests verify default preservation, raw-epoch equality, UTC rounding and offline execution. Its fresh comparison rejects it as a general replacement because three new two-minute errors appear; the public export preserves that counterexperiment without changing the ceiling default. Aggregate reports retain source provenance hashes, with original calendars private.

The additive [Bayynat continuous candidate](../methods/bayynat/CONTINUOUS.md) faithfully relocates the previously reviewed continuous five-marker wrapper, applies uniform nearest-minute rounding, and adds the separately declared existing positive physical factor1 Asr solver. All mapped numerical cores remain unchanged; this later wrapper is outside the original extraction record. Independent arithmetic, raw-event parity, offline tests and complete forecast freezes cover the addition. Reports retain known-data selection, stopped/out-of-picker-range studies, empty responses, and the adaptive equivalent-zoneidentifier probe; no source UTC convention is silently repaired.
