# Local profile registry and source boundaries

The 0.6.0 local registry has 23 profiles. These additional profiles apply named published criteria to the local continuous-solar model and keep source-backed prayer-start rules separate from project-defined markers and software conventions. A profile name identifies its evidence and scope; it is not a complete replica of an institution's timetable, an endorsement, or a religious ruling. The caller selects a profile explicitly. Coordinates and timezone never infer an authority, country, madhhab or Asr choice.

For Egypt and FCNA, the marker conventions are explicit software choices: sunrise and sunset use the flat −50-arcminute model horizon; Dhuhr is an unshifted solar-transit marker; Asr is a factor-one shadow marker; and Maghrib is an unshifted sunset marker. They do not inherit Diyanet Temkin margins, northern policy or institutional prayer-start semantics. Raw model events retain fractional instants and the UI displays nearest-minute values. An absent crossing receives no replacement under these profiles.

The Kemenag profile uses the documented −1° horizon marker and factor-one Asr. Prayer-start minute rules follow the cited example/training account: ceil to the whole minute then add +2 minutes for Fajr, Asr, Maghrib and Isha; ceil then add +3 for Dhuhr. An already exact minute remains unchanged by the ceiling. Sunrise discards seconds by flooring to the minute, then subtracts two minutes. These adjusted values are minute-defined, so the API's `seconds` field is null; the ISO UTC serialization may still show `:00` seconds because it represents an integral-minute instant. This API does not emit the source example's Imsak or Duha columns.

The Kemenag computational domain is latitude −12° through +8°, longitude 94° through 142°, and the four named Indonesian timezones `Asia/Jakarta`, `Asia/Pontianak`, `Asia/Makassar` and `Asia/Jayapura`. This is an implementation boundary for the cited zone-based example, not a statement of Indonesia's political borders or national institutional authority. Its solar engine continuously evaluates the independent USNO model rather than reproducing the printed ephemeris tables; that is an explicit implementation deviation.

For the Egypt/FCNA and Kemenag profiles, a missing physical crossing remains unavailable; none defines a polar fallback. The Diyanet SPA profile has only the bounded northern ordinary guard described in [RULES.md](RULES.md); it does not add a summer twilight estimate. The shared flat-horizon model does not include terrain, observer elevation, local obstructions or topocentric parallax. Displayed minute precision does not establish observed or religious accuracy to the second.

## Source evidence and limits

Dar al-Ifta fatwa 4021 is dated 20 March 2017. It identifies 19.5° as Egypt's adopted Fajr setting and rejects replacing it with the proposed 14.7°. The page's expert discussion associates 17.5° with Isha and 19.5° with Fajr. This supports the named Egyptian angle pair, while neither the fatwa nor the Egyptian Survey service explanation supplies a complete executable local recipe. See [the fatwa](https://www.dar-alifta.org/ar/fatwa/details/13816/فتوى-دار-الإفتاء-المصرية-في-توقيت-الفجر) and the repository's [Egyptian evidence audit](../../methods/egyptian-survey/RULE-EVIDENCE.md).

FCNA attributes its recommendation to the General Body meeting of 27–29 October 2017. Its public guidance specifies 15°/15° in the USA and 13°/13° in Canada throughout the year. It says observation-based caution is recommended, not required, and does not set a fixed minute offset. The webpage's 2026 update metadata is not a new 2026 angle decision. It does not define a full timetable engine, additional prayer-start rules or a universal high-latitude fallback. See [FCNA's recommendation](https://fiqhcouncil.org/the-suggested-calculation-method-for-fajr-and-isha/) and the [repository evidence audit](../../methods/fcna/RULE-EVIDENCE.md).

The Kemenag profile combines the *Ephemeris 2026* worked-example recipe with a Kemenag Temanggung report about training held on 14 April 2016. The report, posted in 2022, describes start signs and explicitly states minute operation and margins. It corroborates that training's calculation sequence; it is not a versioned specification for every current Bimas/SIHAT calendar. A separate Kemenag regional 2025 explanation supports approximately −20° for Indonesian Subuh but does not specify the complete calculator. An 18° comparison is not a full Muhammadiyah profile. See [the training account](https://temanggung.kemenag.go.id/bimbingan-masyarakat-islam/standar-baku-hisab-rukyat-dalam-pelatihan-perhitungan-jadwal-shalat/), the [Subuh explanation](https://kalteng.kemenag.go.id/kanwil/cetak/537222/Soal-Penetapan-Waktu-Subuh-di-Indonesia-Ini-Penjelasan-Kemenag), and the [repository audit](../../methods/kemenag/RULE-EVIDENCE.md).

## Read the coverage fields carefully

`coverage.complete` means every profile output field has a value. `coverage.prayerStartsComplete` means all five prayer names—Fajr, Dhuhr, Asr, Maghrib and Isha—have values and each has the `prayer-start-model` role. Egypt and FCNA currently supply that role only for Fajr and Isha, so their `prayerStartsComplete` is always false; their other geometric markers do not make the missing starts vacuously complete. An app must not present a marker as an authority's selected start merely to fill a six-event display.

The profiles' mathematical equations can be checked independently, but a shared solar model does not upgrade its horizon, coordinates, time scale or rounding into source requirements. These are point estimates under named criteria and implementation conventions, not certified timetables or notification approval. See [local validation](../../docs/LOCAL-VALIDATION.md) for the separate astronomy, rule, date and real-world adequacy checks.
